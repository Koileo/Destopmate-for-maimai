## 1. 运行环境（决定一切技术选型）

| 项 | 实测值 | 对 Mod 的约束 |
|---|---|---|
| 引擎 | **Unity 2018.4.7f1** | 直接加载的 AssetBundle 需匹配此版本；`character.dmc` 是独立数据格式，由运行时重建网格 |
| 脚本运行时 | MonoBleedingEdge / x64 / `scripting-runtime-version=latest` | 可加载 net472 程序集（本工程默认），老版本可退回 net35 |

| 已有 Mod | **AquaMai 1.9.7**（`Mods/AquaMai.dll` + `Package/AquaMai.toml`） | 必须共存：Harmony ID 唯一、不改它的 TOML、层级要低于它的菜单 |
| 画面输出 | amdaemon 配置：2 × **1920×1080，angle 270**；本次实际 `Screen` 为 **1080×1600** | 配置值不能代替运行时窗口尺寸；按实际画布重排，画布不用额外旋转 |

| 现成运行时 | 无 Live2D、无 UniVRM、无 Spine | 当前本地初音由 `PortableCharacter` 重建，无需 UniVRM；自行导入 VRM 可在编辑器阶段使用 UniVRM |

## 2. 分辨率与界面尺寸

### 2.1 基准

- `CanvasScaler` 的参考尺寸仍为 `(1920,1080)`、match=0.5；这只是缩放参考，不能据此推断实际窗口形状。
- 本次游戏实际窗口为 **1080×1600**，竖屏界面按 **1080×1920** 比例装入，主圆区域位于下部。适配后圆心约为 `(540,450)`、半径约为 `450` 个屏幕像素（左下原点）。
- 自动圆形布局先计算 `gameWidth=min(slotWidth,slotHeight*1080/1920)`，圆心 Y 默认 `gameWidth/2`、半径 `gameWidth*CircleRadius`。计算在画布空间进行，避免混用缩放前后的像素。
- `CircleCenterY=-1` 启用上述自动布局；其他值按玩家区域高度比例解释。可显式调整圆心和半径适配其他整合包。横屏、双屏仍需实机确认。
- 圆形模式下角色高度不超过半径的 1.5 倍。头部上方 `HeadFraction=0.20` 的图像可越过圆周；其余身体用 CPU 多边形裁切到圆内，不写游戏 stencil。进场路径为圆外探头 → 停顿 → 移入圆内。

### 2.2 关于 angle 270

输出配置的旋转不能用来推断 Unity 的 `Screen.width/height`。本次运行时已是竖屏 1080×1600。uGUI 画布和游戏 UI 同坐标系，人物不需要额外旋转 270°。
唯一要注意的是：**不要**用 `Camera.main.ViewportToScreenPoint` 之类的屏幕坐标去换算，也不要自己建 `RenderTexture` 后忘了它不带旋转——本 Mod 的 3D 通路是「RT → RawImage」，RawImage 在画布内，天然跟随。

### 2.3 双屏（1P/2P）

单帧缓冲在双人模式下可能变成 **3840×1080**。判断方式很朴素：

```csharp
bool dualWide = (float)Screen.width / Screen.height > 2.4f;
```

- `dualWide == false`：一屏一角色，`PlayerSlot` 自动失效。
- `dualWide == true`：按 `PlayerSlot = 1P | 2P | Both` 把父容器锚定到左半 / 右半 / 整幅。

> 这是防御式设计。不同整合包（含单屏 2P 模拟）表现不同，所以 `Display.PlayerSlot` 是显式配置项，而不是硬编码。

### 2.4 触摸与输入

舞萌的输入不走 uGUI EventSystem，而是 `Manager.InputManager` 的 34×34 触摸网格（`segatools.ini` 里 `io4` / `button` 映射）。
所以本 Mod：

- **不挂 `GraphicRaycaster`**；
- `CanvasGroup.blocksRaycasts = false`、`interactable = false`；
- 所有 `Image` / `RawImage` 都 `raycastTarget = false`。

这样即使未来有人给游戏加了 EventSystem，也不会抢输入。

## 3. 显示层级

```
sortingOrder 32760  ← AquaMai 菜单（示意，需实测）
sortingOrder 20000  ← 本 Mod 画布（默认值，可调）
sortingOrder 0~100  ← 游戏自身 uGUI
（3D 角色在远离游戏画面的专用层，走独立相机 → RT → RawImage，不参与游戏深度/后处理）
```

要点：

1. **必须是 `ScreenSpaceOverlay`**。用 `ScreenSpaceCamera` 会受游戏相机 `depth`/`cullingMask` 影响，且可能被 `BlackoutFadeProcess` 的遮罩盖住。
2. **3D 人物不直接合成到游戏相机**。场景对象位于远处，方案是
   `专用 Layer(30) → 独立正交相机(手动 cam.Render()) → RenderTexture → RawImage`。
3. **不要修改全局渲染状态**：`RenderSettings.ambientLight`、`QualitySettings`、`Camera.main` 一律不碰；灯光只用 `cullingMask = 1 << 30` 的方向光。
4. **不要 `Object.FindObjectsOfType` 全场景扫**，每帧扫会掉帧；一次定位后缓存引用。
5. 蒙皮网格记得 `updateWhenOffscreen = true`，否则相机一偏人物就整体消失（VRM 上极其常见）。

## 4. 触发条件（核心）

舞萌是**进程（Process）驱动**的状态机：`Manager.ProcessManager` 用 `AddProcess / ReleaseProcess` 切换 `ProcessBase` 子类。
「系统闲置」与「用户未登录」就落在两类进程上：

| 阶段 | 进程类（`Assembly-CSharp`） | 说明 | 是否显示 |
|---|---|---|---|
| 开机/启动 | `Process.PowerOnProcess`、`Process.StartupProcess`、`Process.PleaseWaitProcess` | Logo、加载 | ✗ |
| **闲置/招揽** | `Process.AdvertiseProcess` | 标题 Logo、BPM 演出、活动公告（`Monitor.AdvertiseMonitor`） | ✓ |
| 闲置中的广告视频 | `Process.AdvertiseCommercial.AdvertiseCommercialProcess` | 5 分钟上限的那段视频（AquaMai 有 `IgnoreCommercialTimeout` 开关） | 可配（默认 ✓） |
| 闲置中的演示游玩 | `Process.AdvDemoProcess` | 自动打谱演示 | ✓（可关） |
| **未登录/待刷卡** | `Process.EntryProcess` | 投币后进入登录流程，`Monitor.Entry.Parts.ScreenManager` 切换子界面 | ✓（见下表） |
| 游玩 | `Process.GameProcess` | 打歌 | ✗ |
| 结算 | `Process.ResultProcess` 等 | 结算/继续 | ✗ |

### 4.1 Entry 子界面判定

`Monitor.Entry.Parts.ScreenType` 枚举（实测值）：

```
None, ConfirmEntry, ConfirmGuest, DisplayPleaseWait, ConfirmNewAime, ConfirmNewUser,
ConfirmExistingAime, ConfirmInheritAime, ConfirmFreedom, ErrorAime, WaitPartner, DoneEntry,
ConfirmFelica, NoticeFelicaRegistration, ConfirmFelicaSite, DisplayFelicaQR,
ConfirmAccessCode, DisplayAccessCodeQR, ErrorAccessCode, WindowGeneral,
ConfirmExistingAimeContinue, NoticeDataMigration, DispFelicaSiteAndQR, ConfirmSinglePlay
```

「用户未登录」= Entry 流程处于**等待刷卡/等待确认**的界面，即白名单：

```
{ConfirmEntry, ConfirmFelica, ConfirmAccessCode, DisplayAccessCodeQR, DisplayFelicaQR,
 DispFelicaSiteAndQR, ConfirmFelicaSite, NoticeFelicaRegistration, ConfirmExistingAime,
 ConfirmExistingAimeContinue, ConfirmInheritAime, WaitPartner, NoticeDataMigration, ConfirmGuest}
```

`DoneEntry` 一出现即视为已登录 → 立刻开始淡出；`DisplayPleaseWait`（联网取数据）也淡出，避免挡着读盘提示。
未知、空或关闭的 Entry 界面不显示；完成登录标记保持到新一轮 Entry 开始。`FadeProcess`、`BlackoutFadeProcess`、`CommonProcess`、`GenericProcess` 等辅助进程不覆盖真实主进程，也不重置等待时间。

### 4.2 挂接方式

用 Harmony 反射挂接，**不硬编码编译期类型**，这样 1.5x ~ 1.7x 都能用：

```csharp
Patch(ProcessManager, "AddProcess")      → 记录当前进程类型名
Patch(ProcessManager, "ReleaseProcess")  → 当前进程结束时回退
Patch(ScreenManager, "OpenScreen")       → 记录 Entry 子界面（args[0].ToString()）
Patch(ScreenManager, "CloseScreen")      → 清空子界面
```

三个细节：

1. 打 `object[] __args` 而不是具体签名，规避参数类型变更；
2. 目标方法找不到时**只警告、不抛异常**，Mod 退化为「永不显示」，绝不影响游戏；
3. 用 `MelonEnvironment.ModsDirectory` 定位资源，避免工作目录差异。

### 4.3 时间闸门

进程刚切换时，游戏还在做转场/淡入，直接弹人物会很脏。所以：

```
Phase 命中 → 计时 ShowDelaySeconds(默认15s) → 淡入 0.6s
Phase 失效 → 计时 HideDelaySeconds(默认2s)  → 淡出 0.35s
```

滞回的意义：刷卡瞬间 Entry 子界面会连续切换好几次，没有延迟就会疯狂闪。

## 6. 人物资源

当前支持以下路径：

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 2D 序列帧**（推荐先跑） | 从 Desktop-Mate 录屏/截图切帧，或直接用官方立绘，导出 `idle_0.png…` 放 `sprites/` | 零依赖、零版本问题、几乎不吃 GPU | 只有 2D，动作靠帧 |
| **本地 Desktop Mate 数据转换** | CBv3 → 解码检查副本 → `character.dmc` + PNG → 运行时重建 | 保留原模型、蒙皮、骨骼和表情；本机初音已转换 | 原 lilToon、控制器、物理未移植；其他角色需逐个验证 |
| **B. VRM 预制体 + AssetBundle** | Unity **2018.4.7f1** 工程 + UniVRM 0.63（VRM 0.x）→ 导入 VRM → 配 Animator + MToon → 打成 `character.ab` | 3D、可复用 Desktop-Mate 的动作设计 | 需要 2018.4 工程与授权素材；`.cb` 不能直接用 |
| **C. 直接改游戏内已有模型** | 用 `Manager.AssetManager` 取现成 `CharaStateObject` | 素材零成本 | 强耦合版本，且角色风格不符 |

原 `.cb` 和解码后的 Unity 6 Bundle 都不能直接加载到 2018.4；独立数据转换解决的是几何数据兼容，不是整包运行时兼容。原文件保持不变，转换素材只存本地。参考格式来源和工具路径见 README。

## 7. 性能与稳定性红线

| 红线 | 做法 |
|---|---|
| 不能影响判定 | 游玩/结算阶段直接隐藏并**停止 Tick**，不在 `OnUpdate` 里做任何重活 |
| 不能制造 GC 峰值 | 每帧循环不 `new`、不 LINQ、字符串拼接只在状态切换时做；`Animator` 参数用缓存名 |
| 不能抢 GPU | 3D 只在可见时 `cam.Render()`；RT 默认 900×1080；不挂后处理 |
| 不能改全局状态 | 不动 `QualitySettings` / `RenderSettings` / `Application.targetFrameRate` |
| 不能崩在加载 | 每一层（Bundle、预制体、Animator、Sprite）都有独立 try/catch + 降级到 2D |
| 不能和 AquaMai 打架 | Harmony ID 用 `DesktopMateOnMaimai`；不 patch AquaMai 已 patch 的方法；排序层级低于其菜单 |
