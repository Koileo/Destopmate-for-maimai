# 角色动作链：结构、问题与优化方案

> 适用版本：v0.3（2026-11-01）
> 涉及文件：`src/Core/RigDriver.cs`、`src/Core/IdleBrain.cs`、`src/Core/EntranceMotion.cs`、`src/Core/Motion/*`
> 结论：动作从「4 根骨骼 + 3 条正弦」升级为「三层叠加的程序化动作运行时 + 7 段关键帧动作库 + 完整人形链驱动」

---

## 1. 现有动作链的结构（改造前）

### 1.1 逐帧调用链

```
ModMain.OnUpdate
  └─ CharacterPresenter.Tick(dt)
       ├─ 状态闸门（CabinetState）→ alpha 淡入淡出
       ├─ EntranceMotion.Sample(_motionTime)  →  OverlayCanvas.SetEntrance  （屏幕空间位移/倾斜/圆裁切）
       ├─ IdleBrain.Tick(dt)    ── 三轨：状态机 / 眨眼 / 视线
       └─ CharacterStage.Tick(dt)
            └─ RigDriver.Tick(dt)  ── 直接写骨骼 Transform
```

### 1.2 三条并行轨道（DesktopMate 语义的复刻）

| 轨道 | 旧实现 | 频率 |
|---|---|---|
| 状态机轨 | `_mood` 在 Idle/Peek/Stretch/Wave 间按权重迁徙 | 6~14 s，±35% 抖动 |
| 表情轨·眨眼 | `_blinkTime = 0.18f`，用半个正弦做闭眼 | 2.2~5.8 s |
| 表情轨·视线 | 随机目标 + `Vector3.Lerp` 连续平滑 | 2.5~7 s |

### 1.3 骨骼驱动范围（`RigDriver.Tick`）

只写 **4 个** Transform：`Head`、`Spine2`、`Arm_Left`、`Arm_Right`，外加一个 `Eye_Blink` 形变。
模型实际有 22 个可用人形骨骼（`Hips / Spine1 / Spine2 / Chest / Neck / Head / Shoulder_L/R / Arm_L/R / ForeArm_L/R / Hand_L/R / UpLeg_L/R / Leg_L/R / Foot_L/R / Eye_L/R`，已从 `miku-local/character.dmc` 247 个节点中确认）。

### 1.4 进场动作（`EntranceMotion`）

三段纯时间线：探头 `PeekInSeconds`(0.65s) → 停顿 `PeekHoldSeconds`(1.3s) → 身体进入 `EnterSeconds`(1.2s)，
每段一个 `smoothstep`，驱动 uGUI 矩形的位置与倾斜，身体靠圆多边形裁切"显形"。

## 2. 不足之处（按"看得见"的程度排序）

### 2.1 驱动骨骼太少 —— 读作纸片人
躯干只有 `Spine2` 一根在动，`Chest/Neck` 完全静止，所以"转头"实际是"整个上半身硬转"；
没有 `Hips`，就没有重心；没有 `ForeArm/Hand`，手臂是一根直棍；没有腿，站立时膝盖永远锁死。
**这是"缺少细腻动作表现"的第一因**：任何动作都只能表现为整体刚性摆动。

### 2.2 没有过渡帧，动作是布尔开关
```csharp
// 旧代码：挥手只在 -15° 与 -65° 之间二选一，没有中间值
_rightArm.localRotation = _rightRest * Quaternion.Euler(_waveTime > 0f ? -15f : -65f, ...);
```
`_waveTime` 一旦归零，手臂在**一帧内**从 -15° 跳到 -65°（约 50°）。同理 `Blink` 是 `_blinkTime = 0.18f` 的瞬时赋值。
没有缓入缓出、没有预备动作（anticipation）、没有跟随（overlap）、没有收尾（follow-through）。

### 2.3 姿态是"贴"上去的，不是"叠"上来的
旧实现每秒重新用 `_rest * Euler(...)` 覆盖一次，所有通道共用同一个 `_time` 与整数倍频率（0.7 / 1.4 / 0.43 Hz）。
结果：头、脊柱、姿势永远同相位，**呼吸、抖动、摆动同时到顶**，这正是"机械感"的来源；
而真正的手绘待机里，呼吸、重心、头部微动是三条互不同步的曲线。

### 2.4 轴向假设错误，可能把手臂"拧"下来而不是"放"下来
```csharp
_leftArm.localRotation = _leftRest * Quaternion.Euler(-65f, 0f, 0f);  // 绕 local X
```
对 T-pose 手臂来说，local X 是**骨骼自身的滚转轴**（沿手臂方向），绕它转只会让手臂自转（麻花），
真正把手臂放下需要绕角色前后轴（Z）旋转。这一条在不同角色上表现还不一样，因为每个模型导出的 bone roll 不同。

### 2.5 动作库里三个变体是空转
`IdleBrain.Apply()` 下发 `SetTrigger("Peek"/"Stretch"/"Sleep")`，
但 `RigDriver.SetTrigger` 只认 `Blink` 和 `Wave`。也就是说：
**按权重抽到 Peek/Stretch（约占 1/5 的时间）时，角色什么都不会发生，只是静止 3~7 秒。**
加上 `SetFloat("IdleVariant")`、`SetSpeed` 也没有落点，配置项实际是静默失效的。

### 2.6 视线只有头，没有眼，也没有真正的软钳制
`_gaze.x * 18f` 直接加到头部 yaw 上，`Eye_Left / Eye_Right` 两根骨骼从未被驱动；
`GazeRadius = 0.35` 时头最多只转 ±6°，看起来是"脖子在抽动"而不是"在看"。
`LookAtSoftClip` 的本意是"超出范围只转眼球"，旧实现没有实现这个分界。
更关键的是 `Vector3.Lerp(_gazeSmooth, _gaze, dt*2.5)` 是匀速追随，人眼是"跳-停-跳"的**固视（saccade + fixation）**。

### 2.7 眨眼是一条半正弦，且被当成表情用
`SetBlendShapeWeight(_blink, sin(_blinkTime/0.18*π)*100)`：开合对称、没有"快闭慢开"、无双眨；
并且 `Apply()` 里把 `PlayFace("Blink")` 当作 Peek 的"表情"，语义错位。
另外做挥手动作时，`IdleBrain` 的眨眼计时照跑，会出现"笑到一半眨眼"的割裂。

### 2.8 进场是刚体平移，没有领动与落定
头和身体是同一个矩形，一段 `smoothstep` 一起位移；倾斜绕脚旋转，16° 分摊到全身，
看起来是"一张贴纸斜着滑进来"，没有"先探头、身体再跟上、最后站定"的重量变化。

### 2.9 dt 未钳制
`dt` 直接来自 `Time.unscaledDeltaTime`。加载/转场卡一帧 0.5 s，正弦相位会瞬间跳一大截，
进场时间线也会跳过 0.5 s，表现为"人物闪一下位置"。

## 3. 优化后的动作链设计

### 3.1 三层叠加运行时

```
                      ┌──────────────────────────────────────────┐
                      │             MotionRig（新）               │
  时间基 A ──────────►│ 基础层 呼吸(异步周期) + 重心漂移(相位)     │──┐
  手势 clip ─────────►│ 手势层 关键帧增量 × 权重包络              │──┼─► Pose（48 通道）
  视线/眨眼 ─────────►│ 表情层 眨眼状态机 + 视线软钳制 + 表情过渡  │──┘        │
                      └──────────────────────────────────────────┘           │
                                                                             ▼
                                              PoseBinder：语义轴 → 各骨骼世界旋转
                                              （按父链累加，自动适配 bone roll / A-pose）
```

三层的**时间基互不同步**：呼吸相位由噪声轻微加减速，重心漂移有独立相位与周期，
手势层自带淡入淡出。因此不会出现"所有部位同一拍到顶"。

叠加方式：手势层用 **相对静止位的增量**（`dst += (clip - rest) * w`），
而不是整体替换姿态——这样挥手时呼吸不会停、视线不会断。

### 3.2 Pose 通道（语义化，与骨架解耦）

48 个通道，角度为度、位移为米；约定：`pitch>0` 前倾/低头，`yaw>0` 转向角色左侧(+X)，`roll>0` 向右侧倾。

| 段 | 通道 |
|---|---|
| 胯 | `HipsPitch/Yaw/Roll`、`HipsShiftX`、`HipsDropY` |
| 脊柱 | `Spine1/Spine2/Chest` × `Pitch/Yaw/Roll` |
| 头颈 | `Neck`×3、`Head`×3 |
| 肩 | `ShoulderLiftL/R` |
| 上臂 | `ArmDownL/R`（0=T-pose，90=垂手）、`ArmFwdL/R`、`ArmTwistL/R` |
| 前臂/手 | `ElbowL/R`、`WristL/R`、`WristSideL/R` |
| 腿 | `ThighFwdL/R`、`ThighOutL/R`、`KneeL/R`、`AnkleL/R` |
| 表情 | `Blink`、`Smile`、`MouthOpen`、`Squint`、`EyeYaw`、`EyePitch` |

### 3.3 骨骼绑定：语义轴 + 绑定基准

`PoseBinder` 的两条规则：

1. **父链累加**：`worldRot = rootDelta × (qHips × qSpine1 × qSpine2 × qChest …) × bindRot`。
   每一级只加自己的增量，子骨骼自然继承父骨骼旋转（脊柱带动手臂、胯带动腿）。
2. **绑定基准自适应**：绑定期量出「手臂相对水平线下垂多少度」与左右符号（VRM 左侧为 +X），
   运行时用 `ArmDown - restDown`，于是 `ArmDown=74` 在任何角色上都等于"自然垂手"，
   即使某个角色的绑定姿势是 A-pose 也不会穿模。

轴与正负号（已用独立数值脚本逐个复核）：

| 动作 | 轴 | 正角效果 |
|---|---|---|
| 抬/落上臂 | 角色 Z（前后轴） | `ArmDown` 增大 = 手臂下落 |
| 上臂前摆 | 角色 Y | 向 +Z（面向观众）摆 |
| 屈肘 / 抬腕 | 沿上臂的"向前弯"轴 | 前臂/手向前抬 |
| 抬肩 / 塌肩 | 角色 Z | 肩部上提/下沉 |
| 抬腿 | 角色 X | `ThighFwd` 增大 = 膝盖向前 |
| 屈膝 | 大腿的左右轴 | 脚跟向后 |
| 转头 | 角色 Y | 转向角色左侧 |

### 3.4 动作库（7 段关键帧 clip）

| clip | 时长 | 节拍分解 |
|---|---|---|
| `Wave` | 2.90 s | 0–0.18 预备下沉 → 0.52 抬臂 → 0.70 过冲 → 0.92/1.26/1.60 三次摆动（幅度递减，腕比肘晚半拍）→ 1.95 收 → 2.28 落臂过冲 → 2.90 回位 |
| `Peek` | 2.30 s | 0.40 探身+转头 → 0.95 保持 → 1.35 歪头换角度 → 1.75 收回 |
| `Stretch` | 3.40 s | 0.55 抬臂展胸 → 1.25 顶点（张嘴）→ 1.90 停 → 2.45 塌肩收 → 2.85 落臂 |
| `Sigh` | 2.90 s | 0.45 吸气耸肩 → 0.85 吐气垮肩塌脊 → 1.55 余韵 → 2.30 恢复 |
| `Shift` | 3.20 s | 0.85 胯移到一侧（脊柱反向、头回一半、承重腿伸直）→ 1.70 停 → 2.45 回中 |
| `LookAround` | 2.60 s | 0.35 转向一侧 → 0.85 停 → 1.20 快速转向另一侧 → 1.70 停 → 2.10 回正 |
| `Nod` | 1.00 s | 0.26 低头 → 0.44 回弹过冲 → 0.66 二次轻点 |

每段 clip 的第 0 帧就是静止站姿（`ClipLibrary.Neutral`），所以关键帧里只写"改动量"。
每段的淡入/淡出独立配置（`FadeIn`/`FadeOut`），并在结束时给身体一个 **欠阻尼回弹**（`Spring`），
让"落定"取代"急停"。

### 3.5 节奏设计（消除同拍）

| 层 | 设计 | 数值 |
|---|---|---|
| 呼吸 | 非对称曲线：吸气 40%、停 8%、呼气 52%；周期随噪声 ±8% 漂移 | 3.9 s |
| 重心 | 独立相位 + 缓慢变速的正弦，胯先走、脊柱反向、头回一半、承重腿伸直 | 9.2 s，幅度 8 mm |
| 微动 | 每条通道独立种子的 1D 值噪声（两层叠加） | 头 ±1.7°，臂 ±1.4°，肘 ±1.8° |
| 固视 | 60% 看玩家、40% 扫向一侧；固视 0.9~3.2 s 后跳一次 | 眼球 τ=0.05 s，头 τ=0.30 s |
| 眨眼 | 闭 0.07 s（ease-in）→ 停 0.03 s → 开 0.13 s（ease-out），18% 概率二连眨 | 间隔 2.4~6.4 s |
| 手势间隙 | 大动作后至少 6~14 s；抽到 "Idle" 时 84% 概率插入微动作（Shift/LookAround/Nod/Sigh） | 避免长空档石化 |

同一动作不连续出现两次（`_lastMood`），避免复读感。

### 3.6 进场四段式

| 段 | 变化 |
|---|---|
| 探头 `0.65s` | 位移用 OutCubic（快出慢收）；倾斜用 **OutBack**（过冲约 10% 再回来），像真的探头 |
| 停顿 `1.3s` | 保持歪头，等观众注意到 |
| 进入 `1.2s` | InOutCubic 位移 + 倾斜归零 + **横向弧线**（路径不是直线，像从桌边绕进来） |
| 落定 `0.35s`（新增） | 整体下沉 7 px 后回弹，倾斜 ±1.8° 衰减振荡，必须严格衰减到 0（否则每帧采样都会抖） |

### 4.1 关键代码对照

```csharp
// 旧：挥手是布尔跳变
_rightArm.localRotation = _rightRest * Quaternion.Euler(_waveTime > 0f ? -15f : -65f, ...);

// 新：关键帧 + 权重包络 + 增量叠加
_clip.Sample(_clipTime, _clipPose);
Pose.AddDelta(_out, _clipPose, _clip.Rest, _clipWeight * _intensity);
```

```csharp
// 旧：绕骨骼自身滚转轴放手臂
_leftArm.localRotation = _leftRest * Quaternion.Euler(-65f, 0f, 0f);

// 新：在父链语义空间里绕角色前后轴外展，并沿链累加
Quaternion armQ = Quaternion.AngleAxis(-side * fwd, Vector3.up)
                * Quaternion.AngleAxis(-side * down, Vector3.forward)
                * Quaternion.AngleAxis(side * twist, Vector3.right);
Quaternion qArm = qShoulder * armQ;
SetJoint(ref arm, rt * qArm);   // rt 为根增量，SetJoint 内部乘绑定旋转
```

- 落定下沉改为零位移、零速度起步的包络，默认 0.35 秒时，60fps 采样最大下沉约 7.16px、回弹约 2.69px、最大单帧位移约 2.85px；落定关闭时不产生额外位移。
- 关节方向用独立四元数脚本复核：左/右上臂 74° 下垂对称、屈肘向前(+Z)、屈膝向后(-Z)、转头/低头方向正确、抬肩方向正确。

**本机游戏验收与适用范围**

- 已在本机 1080×1600 游戏窗口验证初音的单一 Idle、进场与七段动作；Stretch 的抬臂角度和前伸量根据实际截图修正。第二轮 393 张人物图无取景边缘裁切。方法、截图与数据范围见 [06-动作验收.md](06-动作验收.md)。其他角色和动作倍率需分别确认。
