# v0.4 屏内角色表现验收

日期：2026-11-01（北京时间）。本机 SDEZ 1.70、Unity 2018.4.7f1、MelonLoader 0.6.4、AquaMai 1.9.7，1080×1600 游戏窗口，`miku-local`，人物图 756×1080。

## 表演与布局

默认流程为：0.72 秒探头扶边 → 2.55 秒看向玩家、微笑并错拍挥手招呼 → 1.55 秒沿圆弧跨入 → 0.35 秒落定 → 屏内常驻。呼吸、重心、眼神与眨眼继续独立运行；随机手势只在常驻阶段开始。探头点贴近圆边，先露出上半身供扶边和挥手，身体继续由圆周裁切。

入场骨骼直接采样空间时间线，调整待机 `MotionSpeed` 不会改变招呼与跨入的同步。阶段切换用 0.16 秒混合保留旧姿态；0.1 秒以内的每帧时间拆为不超过 1/60 秒的小步，避免低帧率时骨骼只前进一半时间。修复总时长浮点减法误差造成状态永久卡在 Settling 的问题。

以圆心为原点、圆半径为 1，信息保护边界为 `x >= 0.48`、`y >= -0.28`。人物大小按整张图的宽高比求解，常驻矩形必须装进右侧空白带与圆的交集，并为倾斜、落定下沉留余量。手和头发只要在人物图内，就同样参与包络计算。头部与身体的实际网格也裁切到信息保护边界，不写入游戏 stencil、不拦截触摸。位置配置是期望值，会受安全布局限制。

一轮招揽只进场一次。普通转场冻结空间并原地淡出，恢复时继续原进度；广告完全淡出再回到标题也不重播进场。登录或游玩结束一轮玩家会话，下一轮招揽才允许新的进场。

## 自动与游戏内验证

- Release 构建：0 警告、0 错误。
- 29 项显示流程检查：包含完整淡出后的广告循环、游玩后的新一轮进场，以及总时长精确终点启用待机。
- 51 项动作检查：包含 0.5、0.7、0.833、1.0、1.5 五种人物图比例的可见矩形避让与常驻圆内包络；0.2、1.0、2.5 三种速度的进场同步；手势切换无一帧归零；10fps 时间推进；全部 10 段动作完整结束。
- 游戏内第二轮采集 884 帧，阶段顺序为 Peeking → Calling → Entering → Settling → Inside，没有倒退；无 NaN 或 Infinity。
- 81 组游戏截图与人物图；人物图 alpha ≥ 24 的可见像素均未触及贴图边缘。
- 原地完全淡出前、透明度为零期间、恢复后，进场时间均为 5.17 秒。恢复后位置与淡出前一致，未重播探头或跨入。
- 本机配置 SHA256 验收前后一致；临时 QA 模块仅在内存中控制测试流程，已从游戏 Mods 移除，测试进程已退出。构建 DLL 已安装到本机 Mods。

本地逐帧 CSV、PNG、分析结果、日志与旧 DLL 备份保存在 `.tools/presence-qa/`，不进入发布包。

## 验收范围

画面与信息避让验证针对上述 SDEZ 标题/招揽布局和本机初音。其他角色、不同游戏 UI、完整刷卡/二维码流程、双屏、触摸、AquaMai 菜单和长时性能需要分别验收。旧 AssetBundle/2D 资源仍按阶段触发 Call/Enter（缺失时回退 Wave/Shift）；按时间线精确采样的骨骼效果适用于本地 DMCHAR01 角色。
