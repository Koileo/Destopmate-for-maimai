## 2. 文件清单

| 文件 | 职责 | 关键点 |
|---|---|---|
| `src/ModMain.cs` | MelonMod 入口、生命周期、延迟建 UI、分辨率变化重排、热键 | `[assembly: MelonGame("sega-interactive","Sinmai")]`；启动后延迟 3s 再建画布 |
| `src/Config/ModConfig.cs` | 强类型配置 + 首次运行写模板 | 解析失败回落默认值，不抛异常 |
| `src/Config/TinyToml.cs` | 极简 TOML 子集解析 | 不引第三方库，规避与 MelonLoader/AquaMai 的版本冲突 |
| `src/Core/CabinetWatcher.cs` | Harmony 挂接 `ProcessManager` / `ScreenManager`，维护 `CabinetState` | 全部按**字符串类型名**判断；`object[] __args` 规避签名差异 |
| `src/Core/OverlayCanvas.cs` | 画布、CanvasScaler、层级、贴靠布局、双屏切分 | 不挂 GraphicRaycaster；`blocksRaycasts=false` |
| `src/Core/CharacterStage.cs` | 3D/2D 两条渲染通路 | 3D：层隔离 + 手动 `cam.Render()` + RT；蒙皮 `updateWhenOffscreen=true` |
| `src/Core/CharacterDriver.cs` | `ICharacterDriver` 抽象 + 两个实现 | 上层只认 8 个动作原语（对齐 DesktopMate 的 SDK 动作集） |
| `src/Core/IdleBrain.cs` | 待机逻辑：状态机轨 / 抖动轨 / 表情轨 | 权重随机 + 时长抖动 + 视线软钳制 |
| `src/Core/CharacterPresenter.cs` | 状态 → 透明度 → 可见性 | 双段滞回（显示快、隐藏留缓冲） |
| `src/Core/CharacterLoader.cs` | Bundle/预制体/序列帧加载与缓存 | 版本不匹配给出可读错误 |
| `src/Core/PortableCharacter.cs` | 读取 DMCHAR01，重建骨架、网格、蒙皮、材质和表情 | 不加载 Unity 6 脚本或 Shader；资源统一释放 |
| `src/Core/RigDriver.cs` | 本地初音骨架的程序待机、视线、眨眼、挥手 | 不包含原动作控制器或物理 |
| `src/Core/EntranceMotion.cs` | 圆外探头、停顿、进入的纯时间线 | 与状态闸门分开，可无界面验证 |
| `src/Core/CircleClippedImage.cs` | 身体多边形裁切到圆内 | 复用数组，不使用会干扰游戏的 stencil Mask |
| `tools/read_character_bundle.py` / `export_local_character.py` / `validate_portable_character.py` | 本地离线转换与独立数据检查 | 原始文件不修改，转换输出不随源码分发 |
| `assets/DesktopMate.toml` | 默认配置（带中文注释） | 与 `ModConfig` 字段一一对应 |
| `DesktopMateOnMaimai.csproj` | `net472` 工程，引用游戏 DLL 与 MelonLoader | `-p:MaimaiDir=...` 指定 Package 目录 |
| `build.bat` | 构建 + 安装到 `Mods` + 铺资源目录 | 需要 .NET SDK |

## 3. 数据流（一帧）

```
OnUpdate
  ├─ CabinetState.PhaseSeconds += dt          // 状态持续时间
  ├─ HandleHotkey()
  ├─ 分辨率变化？→ OverlayCanvas.ApplyLayout
  └─ Presenter.Tick(dt)
        ├─ 读 CabinetState.ShouldShow(cfg)     // 进程 + Entry 子界面 + 配置
        ├─ 游玩/结算且 HideDuringGame=true：立即隐藏，停止动画与渲染
        ├─ 滞回计时（Show 0.05s / 普通 Hide 2s；DoneEntry/DisplayPleaseWait 立即开始淡出）
        ├─ alpha 线性趋近 → CanvasGroup.alpha = alpha * Opacity
        ├─ EntranceMotion → 圆外头部位置/倾斜 → 进入圆内，身体裁切到圆内
        ├─ 可见时：
        │    ├─ IdleBrain.Tick(dt)             // 三轨
        │    └─ Stage.Tick(dt)                 // 3D: cam.Render() / 2D: 帧推进
        └─ 不可见时：不推进角色动画、不 Render（仍检查状态）
```

## 4. 实现要点（按坑排序）

1. **建 UI 的时机**：`OnInitializeMelon` 里建 Canvas 可能被首个场景加载清掉。本工程延迟 3 秒在 `OnUpdate` 里建，并且 `DontDestroyOnLoad`。
2. **层级不要用负数/超大值**：`sortingOrder = 20000` 是「高于游戏、低于 AquaMai 菜单」的折中；被挡或挡人都只改配置。
3. **3D 必须层隔离**：`Camera.cullingMask = 1 << CharacterLayer`，模型、灯光递归设层。忘了设层 → 人物「消失」或「照亮全场」。
4. **蒙皮必须 `updateWhenOffscreen = true`**：否则相机动一点人物整体消失，是最常见的「玄学 bug」。
5. **正交相机 + 归一化**：模型统一缩到 1.8 世界单位高、脚在 y=0，`orthographicSize = height * 0.53`，换角色不用改取景。
6. **Patch 失败要静默降级**：目标方法改名（SDEZ 版本差异）时，Mod 应该「什么都不发生」，而不是崩溃。
7. **Entry 子界面必须白名单**：`ScreenType` 有 24 个值，用白名单收「等待刷卡」，其余一律不显示，避免登录后还挂着人物。
8. **不要在 `GameProcess` 里跑任何逻辑**：`HideDuringGame` 命中后 `Presenter` 直接返回，`OnUpdate` 里也不做字符串比较以外的活。
9. **资源生命周期**：当前启动延迟结束后加载一次角色，隐藏时保留资源，退出时才 `Dispose` / `UnloadAll`；逐局卸载尚未实现，长时运行需实测。
10. **配置健壮性**：任何字段解析失败只回落默认值；`IdleWeights` 数量与 `IdleVariants` 不匹配时按 1 补齐。

## 5. 实施里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| M1 | 画布 + 2D 序列帧 + 状态监听 | 闲置 15s 出现静态立绘，刷卡后消失，无输入影响 |
| M2 | 淡入淡出 + 布局配置 + 热键 | 改 toml 重启即生效；1600×900 窗口不跑位 |
| M3 | `IdleBrain` 三轨（眨眼/视线/待机变体） | 连续闲置 10 分钟不重复机械感，无状态卡死 |
| M4 | 3D 通路（2018.4 导出的 `character.ab`） | 人物边缘干净、不被 Note 遮挡、无穿模 |
| M5 | 双屏/双人适配 + 相册一拍 | 1P/2P 各自正确贴靠 |
| M6 | 与 AquaMai 共存验证 | 菜单可正常呼出、不互相遮挡 |

## 7. 适配确认状态（2026-11-01）

1. 双人模式 `Screen.width` 到底是 1920 还是 3840 —— 用 `> 2.4` 宽高比自动判别，且 `PlayerSlot` 可强制指定。
2. AquaMai 菜单的真实 `sortingOrder` —— 若被遮挡，把 `Display.SortingOrder` 调到 1000 以下。
3. 已检查本机 `Assembly-CSharp.dll`：`AddProcess(ProcessBase, byte) -> uint` 无重载，`ReleaseProcess(ProcessBase) -> void`。其他整合包仍需核对。
4. 已确认本机 `OpenScreen(ScreenType, object[])`、`CloseScreen(bool)`；前者内部会调用后者。关闭界面不再视作等待刷卡，`DoneEntry` 状态保持到新进程开始。
5. Release 构建与安装完成（0 警告、0 错误）；20 项无界面判定检查通过。包括辅助进程不重置闲置计时、进场三阶段和加载失败不显示空白面板。测试命令见 README。
6. 本地初音导出通过独立校验：247 节点、4 网格、30,280 顶点、47,272 三角形、23 表情形变。已确认 Harmony 实际挂接，实际窗口 `Screen=1080×1600`，角色可经独立 RT 合成进游戏。
7. 已逐张检查实际游戏的探头、进入和站立截图，证据见 `images/entrance-check.png`；24 位深度及收紧的相机远裁面修复衣服深度闪点。本机配置为 3D 初音、Yaw=180、闲置等待 18 秒，诊断截图已关闭。
